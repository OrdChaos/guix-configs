# Runtime Language, System/Home Ownership and SSH Policy

## J1 — Runtime Language Policy

Runtime and interactive messages emitted by guix-config are **English**,
because early boot and Linux virtual consoles cannot assume CJK fonts.

- Covered: every runtime-facing string guix-config owns — initrd / serial
  console / password fallback / Recovery / install CLI / tpm2-enroll CLI /
  commit-root / deploy — is English ASCII (no emoji, no decorative
  Unicode, no CJK punctuation).
- Enforced by `tests/test-ui-language.scm` (fails on Han characters in
  runtime-call string literals across modules/ and tools/).
- Not covered: upstream output (Guix, cryptsetup, OpenSSH, kernel).
- Comments, docstrings and test descriptions stay in Chinese.

Terminology is unified: Secure Boot, Setup Mode, Recovery, TPM
enrollment, TPM auto-unlock, recovery passphrase, system partition, ESP,
root generation, last-good system, Recovery candidate, deploy, promote.

## J2 — System/Home Boundary

Guix System owns:

- machine users/groups, /etc/passwd login shell
- filesystem/mount topology, user persistence mappings
- sshd, SSH server policy, SSH host keys, authorized-keys policy
- system services, boot/security

Guix Home owns:

- user packages, shell rc/config, aliases, environment
- Git config, dotfiles, user environment variables
- user services (SSH client config and desktop config later)

Persistent data layer owns:

- user-created persistent data, SSH host private keys
- later application state / private secrets

Home does not mount /persist, does not manage sshd, does not create
private keys. System does not rebuild user data.

## J3 — SSH Policy (current VM)

- normal user password login: **allowed**
- public key authentication: **allowed**
- root SSH login: **prohibited completely** (every authentication
  method: password, public key, keyboard-interactive)
- empty passwords: disabled
- port: 22

Effective enforcement: `PermitRootLogin no` + `DenyUsers root`
(defense-in-depth); host keys only from `/persist/system/ssh/`
(ed25519; first boot auto-generated by activation, root-owned, private
0600, public readable) — stable across root-generation reboots.

## J4 — Persistent Home Policy

`/home/user` itself remains **ephemeral** (stateless root). Initial
persistent directories (bind-mounted by the system from
`/persist/data-home/user/`):

- guix-configs
- Projects
- Documents
- Downloads
- Pictures

Explicitly ephemeral (not persisted in this round): `~/.cache`,
`~/.config`, `~/.local`, `~/.mozilla`, `~/.steam`, whole HOME.
This round does not claim full user state persistence.

## J5 — Guix Home Environment across Reboots

`guix home reconfigure` writes nothing into `/persist` itself: the home
generation lives in `/var/guix/profiles/per-user/<user>` and
`/gnu/store` (both persistent subvolumes). What lives in the ephemeral
`$HOME` is only a set of symlinks:

- `~/.guix-home` -> the current home generation
- `~/.gitconfig`, `~/.bash_profile`, `~/.bashrc`, `~/.profile`, ...
  -> generation `files/` entries

Since the ephemeral root is recreated at every boot, those symlinks
vanish on reboot (the environment appears "uninstalled" until
`guix home reconfigure` is re-run by hand).

System-side guarantee (owned by `user-persistence` module): the
one-shot shepherd service `home-env-reapply` runs once `file-systems`
is up (before login/sshd) and re-creates the symlinks from the latest
home generation chain — no manual re-run needed after reboots. It
never overwrites a real (non-symlink) file in `$HOME`, and it is a
no-op while no home generation exists. `~/.cache`, `~/.config`,
`~/.local` contents stay ephemeral as per J4.
